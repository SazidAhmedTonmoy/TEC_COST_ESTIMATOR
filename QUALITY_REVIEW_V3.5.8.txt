TEC ConEst v3.5.8 — Release verification
Prepared 22 October 2026

VERIFIED LOCAL RESULT

The release passed 390 Python tests across 52 modules,
17 JavaScript test files, TypeScript checks, both
production interface builds, and 24 Chromium browser checks.
The browser recorded 18 screenshots and no unexpected
page, console or HTTP errors. Backend and contained-server tests used exact
SQLite 3.34.1, matching the supplied hosting diagnostic. Test databases were
temporary. The original application database hash is unchanged.

One older workbook test expected a 24-point instruction row. The added
optional-cost help uses a 30-point row. Only that expected height was updated;
its complete 10-test module was rerun successfully. The remaining 51 modules
passed in the full gate. No application behavior was changed for that rerun.

EXPIRED OPPORTUNITY ACTIONS

Assigning a team to an expired opportunity still approves it without changing
its deadline. Approved opportunities with past regional deadlines no longer
offer Quoted or Not quoted on cards or in details. Existing recorded quotes
keep their receipt and Chase-up link. No date-based conversion or inferred
submission link is written. Assigning an old project creates no extra quote.

Expired records and approved past-deadline records without a recorded quote
offer Reject. A blank note is accepted. The decision is recorded with its
actor and time, activity, notifications and contribution event. Rejection of
an approved old opportunity is an ordinary decision; it does not manufacture
a Not quoted outcome. Current approved Not quoted behavior remains available.

Server authority and revision checks remain in place. Either a quoted flag or
existing submission links protect a project from repeated quotation and from
rejection through Opportunities. A new quote request after its deadline is
rejected before writes. A previously successful quote's identical retry still
returns the original submissions after expiry. Tests cover today, yesterday,
blank dates, denied users, linked legacy records, retries and unchanged data
after rejected requests.

The policy applies to approved records with a past deadline, whether or not
an older external Chase-up record has an explicit opportunity link. This
release does not guess matches between unlinked legacy projects.

DEADLINE DISPLAY AND MOBILE UI

Approved, rejected and expired records use readable grey deadline text with
no urgency background. Past-due pending records are also neutral while waiting
for their normal expiry update. Active pending records retain red for today
through 3 days, amber for 4–7 days, and green for more than 7 days. The same
regional calendar drives the day count and action eligibility. Existing
regional-midnight scheduling is preserved without additional API polling.

Browser checks use actual compiled interfaces and normal clicks. They cover
card/detail rejection, expired team approval, a two-builder future quotation
and its Chase-up receipt, deadline boundaries, and 320px/390px dark and light
layouts. Existing card-action modal separation and explicit quote form labels
remain intact. New rejection buttons are checked for visibility and click
coverage. Key desktop/mobile screenshots are reviewed before packaging.

ESTIMATE SWITCHES AND OPTIONAL COSTS

Visible On/Off words are removed. The switch remains a native button with
role=switch, its accessible inclusion label, aria-checked state, keyboard focus
and a 44px minimum hit area. Editing authority and saved section state are
unchanged. Deselecting a section keeps raw items and prices and labels it
Optional cost. Its values remain excluded from included project totals.

New Excel exports display Included or Optional cost for numeric inclusion
flags, and separate Optional quoted cost from the Included estimate total.
The detail sheet includes optional material, hours, labour, direct and quoted
totals. Optional quoted values use the same component and item markup formulas
as included work. Only parent costs are aggregated; components are not counted
twice. Category summaries retain raw optional prices and label them clearly.
Work-type totals continue to include selected items only. Print areas include
the optional subtotal.

Focused tests check mixed inclusion, all included, all optional, empty exports,
item markup exemptions and component price edits. An independent arithmetic
evaluator traces workbook formulas against application totals. Artifact Tool
also imports the actual application export and recalculates representative
input changes. The sample reconciles as follows:

  Saved settings       AUD 265.23 included, AUD 1,427.37 optional
  All included         AUD 1,692.60 included, AUD 0.00 optional
  All optional         AUD 0.00 included, AUD 1,692.60 optional
  Original restored    AUD 265.23 included, AUD 1,427.37 optional

The workbook error scan returned no formula errors. Summary and detail views
were rendered and reviewed for labels, totals and readable cost-treatment
controls. No workbook was rewritten by the verification tool. Native desktop
Microsoft Excel was not available for a separate native-application run.

SHARED LINKS, PERSISTENCE AND SECURITY

Public shared estimates show a separate Optional costs summary and label
optional categories and items. The main included total excludes those amounts.
All-optional projects show a zero included total; all-included projects hide
the optional summary. The same link updates on reload when saved selections
change. Anonymous browser checks verify displayed included and optional totals
against the server calculation, preserved raw prices and mobile layout.

The existing share token hashing, creation/revocation permissions, read-only
route, no-store response and content-security policy are unchanged. The new
summary neither changes project data nor introduces a new sharing permission.

After normal deadline processing, a real server stop/start preserved opportunity
states and notifications, saved quote submissions, estimate exclusions/totals/
line identities, and the public shared HTML. Both private databases passed
integrity_check and foreign_key_check before and after restart. Deep readiness
reported release 3.5.8, schema 32, and successful tenders, opportunities,
timezones and sqlite checks.

REGRESSION SCOPE AND PACKAGE CHECKS

The backend gate includes earlier schema migrations, retained-record reset,
legacy parent/builder constraints, approval restoration, permissions, imports,
notifications, quote transactions, estimate totals, revisions and sharing.
There is no new schema version, dependency or reset in this release.

The package builder validates Python 3.11 syntax, release/schema constants,
both interface indexes and referenced compiled assets. ZIP integrity and file
hash checks verify full and changed/new-file archives against the immutable
previously delivered v3.5.7 full ZIP. Overlaying the patch supplies the same
current application files as the full release. Retired hashed assets may
remain as the only overlay extras. Working Passenger configuration and
requirements remain unchanged. No runtime database, credentials, uploads,
private QA fixture or dependency cache is included. The opportunity import
template is unchanged; the Excel changes apply to estimate exports.

LIMITS

Backend execution used Python 3.12.3 with the host's SQLite 3.34.1. Python 3.11
syntax is checked separately; this environment did not execute the host's
exact Python 3.11.13 build. Production data and the live hosting account were
not accessed, changed or deployed. Local passing checks do not establish that
the host has reloaded the new package. Complete the upload and restart steps
in UPDATE_INSTRUCTIONS_V3.5.8.txt and verify deep health after deployment.
