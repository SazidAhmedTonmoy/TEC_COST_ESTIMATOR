TEC ConEst v3.5.6 — Release verification
Prepared 21 October 2026

RESULT

The release passed 347 Python tests across 47 modules, eight JavaScript display
test groups, TypeScript checking, the production frontend build and 31 browser
checks. The backend and browser-server runs used SQLite 3.34.1, matching the
version reported by the hosting diagnostics. The browser run produced 17
screenshots and reported no page, console or HTTP errors.

The release is prepared for deployment. These checks ran locally against
disposable databases; they do not establish that the production host has
received the files or restarted. Follow UPDATE_INSTRUCTIONS_V3.5.6.txt and check
the running release after upload.

CONFIRMED DATABASE CAUSE AND REPAIR

The latest reported error was reproduced with the previous release and a
legacy table requiring opportunities.creator_id:

  NOT NULL constraint failed: opportunities.creator_id

The current writer supplies created_by, so the older NOT NULL column prevents
an insert even when all visible form fields are valid. A fresh local database
does not contain that obsolete requirement.

The updated migration examines actual table constraints and rebuilds supported
incompatible layouts transactionally. It retains the complete original table
as an archive, copies verified current columns into the canonical table, and
rebinds affected current application foreign keys to the current parent.
Historical dependencies and original metadata remain with the archive. A
verified database backup precedes migration; foreign-key enforcement stays on.

The new parent-migration tests cover extra required columns, nullable/default
differences, outgoing references, additional constraints, current dependent
tables, historical dependents, indexes/triggers, preserved activity sequences,
creator recovery, interrupted/failed migrations and repeated startup. Tests
also verify that an archive's original body and metadata are not rewritten by
column recovery or legacy update triggers.

Runtime reading now recovers a missing JSON createdBy value from the genuine
stored created_by column. An explicit JSON value remains authoritative. This
preserves creator permissions and prevents the next legitimate edit from
accidentally clearing a recovered creator. No placeholder user is invented.

The existing one-time reset completion key, retired membership and history are
preserved. A completed reset does not clear projects created or imported later.
The earlier missing-column, builder migration, foreign-key/reset and retention
regressions remain covered by the suite.

FRONTEND AND MOBILE VERIFICATION

The production Vite build and TypeScript --noEmit check passed. Existing shared
runtime scripts remain served separately; the browser checks loaded them
successfully with no missing-asset responses. No new application dependency
was introduced.

Eight JavaScript test groups cover URL display and regional day calculations,
including invalid dates, leap dates, daylight-saving boundaries and status
wording. The day count uses the opportunity region, not the viewer's timezone.

The final Chromium run checked the compiled application at a 1440px desktop
width and at 390px and 320px mobile widths, with both mobile themes. It:

- Created a pending opportunity with an existing builder, a new builder and a
  bare Link, then verified HTTPS storage and the card/detail anchors.
- Changed Link, reopened it, cleared it and verified persistence at each step.
- Confirmed Contact person and Email are absent from the forms and save payload.
- Confirmed cards retain their exact closing date and show days remaining.
- Checked cards, forms and detail panels for horizontal overflow.
- Focused and filled the mobile Link input, measured its entire visible box,
  and hit-tested five points to ensure action buttons do not cover the input.
- Confirmed long detail URLs occupy at most three visible lines while retaining
  their complete target and title. The editor retains the complete value.
- Checked today, tomorrow, expired, rejected and undated card wording.
- Checked that an unsafe historical URL is not displayed as an active link.

Controlled-clock checks used an America/Los_Angeles browser timezone with NSW,
VIC and a separately configured WA region. NSW and VIC changed at their own
midnight; WA stayed on its local day. Opportunity request counts stayed at
two before and after the transition: the countdown adds no API polling.
The existing refresh behavior remains in place.

All 17 screenshots were inspected during verification, including the final
mobile form and detail corrections.

RESTART, READINESS AND DATA INTEGRITY

After the real browser workflow, normal deadline processing was completed on
the private QA databases before taking a restart checkpoint. Opportunity IDs,
status, revisions, Link and notification count then matched across restart.
Both databases passed integrity_check and foreign_key_check before and after
restart. Deep readiness returned release 3.5.6, schema_version 31, with tenders,

An independent check explained the first upcoming reminder after an immediate
restart: a newly created project due in five days had not yet reached the
normal 60-second sweep. Its counts were 3 before the first restart, 4 after
the first and 4 after the second. Exactly one upcoming event existed and the
record was unchanged. The final checkpoint completes this legitimate work
first, then retains strict equality across restart.

EXCEL TEMPLATE

The supplied workbook and the application's Download template file are
byte-identical. The blank template has 14 columns, headings on row 7 and 100
empty entry rows beginning at row 8. It retains its native Excel table, frozen
panes, date/number formats, region/date/number validation and Instructions tab.

The last three columns are Link (L), Notes (M) and Added Date (N). Shared
Contact person and Email columns are absent. The template was rendered and
visually checked, then read back and exercised by the import tests.

Import accepts plain URL text and Excel's native Insert > Link relationship,
including a friendly display label. Export retains the actual URL with a
clickable hyperlink. Formula cells such as HYPERLINK(...) receive a clear
validation message; formulas are not evaluated. Legacy contact columns remain
source information and are not reintroduced into the current shared form.

v3.5.5 full archive. It contains changed/new files and release metadata. The
full archive supplies current application code and compiled frontend assets.
Package verification checks ZIP integrity, every member hash and a simulated
v3.5.5-plus-patch overlay against the full v3.5.6 contents. The only allowed
overlay extras are retired hashed frontend assets, which may remain while old
browser tabs or workers finish using them.

The archives exclude live databases, uploads, environment credentials, backups,
cache directories and node_modules. The working-tree catalog database's SHA-256
