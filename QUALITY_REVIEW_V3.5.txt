OPPORTUNITY AND DATA COVERAGE

administrator and team-member decisions, live account/team checks, invalid
permission escalation, optimistic revision conflicts, regional expiry,
idempotent deadline events, assignment notifications, per-user read receipts,
retained deletion audit and paginated activity.

The 54 packaged opportunities match the supplied workbooks: NSW 7 and VIC 47.
Workbook fidelity checks cover dates, budgets, builders, preserved source flags,
missing-builder warnings, source rows and literal text. Import tests cover
add-only behavior, changed duplicates, stable exported IDs, deleted records,
validation, formula results, new-region origins, preview invalidation and
transactional application. Export/import round trips preserve the supported
fields and multiple builder names.

Contribution tests confirm opportunity actions appear in their own workflow,
mirrored Tender audit rows are not counted twice, imports are attributed to
the actual user, region settings are not counted as file uploads, and deletion
does not remove contribution history.

Separate visual checks covered Home, Opportunities and forms at 390, 600 and

DATABASE LIFETIME AND RESTART CHECKS

Three additional automated tests exercised 50 committed updates, 90 detail
reads, 25 inbox cycles, 10 actual backups/checkpoints, explicit/automatic
connection cleanup and five Store shutdown/restart cycles. They preserved a
stable WAL inode and passed final SQLite integrity checks.

The final controlled browser gate then stopped and restarted the actual HTTP
server against the same private database files. Opportunity IDs, revisions,
statuses and notification counts were unchanged, and the approved test record
remained approved. Both the Estimator and Tender databases passed full
integrity_check and foreign_key_check before and after that restart.

The actual deadline CLI was run twice against separate temporary databases;
the opportunity expired and retained exactly one expiry event. Cron-generation
tests confirm reinstallation preserves unrelated jobs and the daily backup.

DEVELOPMENT DIAGNOSTIC LIMIT

Two earlier long-lived test sessions showed a SQLite WAL pathname referring to
an older file while the running server held a newer, unlinked WAL. The exact
replacement mechanism was not established. The final controlled execution
described above did not reproduce that condition and passed all integrity and
restart checks. The release adds explicit Tender connection lifetimes, but
does not claim that change alone proved the cause or repaired those test files.
No automatic WAL deletion or database repair was added. Diagnostic copies
remain separate from the release; production hosting was not inspected.

FIXES CONFIRMED DURING REVIEW

- Opportunity detail controls remain clickable after approval/edit dialogs.
- Import previews no longer render a stray zero for an empty warnings list.
- Contribution history labels and actions no longer overlap.
- Shell launchers use Unix line endings for Linux/macOS compatibility.
- Updated local launchers detect the new time-zone dependency.
- Tender migration/backup connections close deterministically and the shared
  store retains an idle connection during service, releasing it on shutdown.

PRACTICAL LIMITS

The browser checks used Chromium on Linux. The Windows launcher was reviewed
and updated, but was not executed on Windows. No production load benchmark was
performed. Distances are source/manual values; the route link does not compute
or store automatic road distances. Import adds missing opportunities only;
existing changed rows are reported and preserved for editing inside the app.

Read UPDATE_INSTRUCTIONS_V3.5.txt for installation and preservation of live
data. CHANGED_FILES_V3.5.txt and V3.5_FILE_MANIFEST.json identify the exact
changed/new files and SHA-256 values used in the release archives.
