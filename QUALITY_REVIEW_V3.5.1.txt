TEC ConEst v3.5.1 — Verification and deployment notes
Prepared 21 October 2026. Estimator schema remains 31.

RESULT

The updated code, blank import template and owner-requested one-time
opportunity reset passed the checks below. This package has not been deployed
to the live website. Its production opportunity data has not been cleared
during this work. The clear runs on the first Tender initialization after
installing this release, including the deeper deployment health check.

CONFIRMED HOSTED OBSERVATIONS

The public /api/health endpoint returned HTTP 200, release 3.5 and schema 31.
/tenders/ returned its shell. Unauthenticated session and Tender bootstrap
requests correctly returned 401. A browser without an existing session reached
the normal sign-in page.

The old frontend discarded unsuccessful bootstrap JSON and replaced it with
the generic session error in the screenshot. The update preserves HTTP status
and safe error references, logs the original exception under that reference,
and keeps valid sessions during Tender startup failures. The actual
authenticated production exception remains unconfirmed: no production
traceback or authenticated hosted session was available.

RESET VERIFICATION

Private fixtures confirmed a consistent, verified pre-reset Tender backup;
removal of active and soft-deleted opportunity rows, assignments, edit grants,
deadline keys, opportunity builders and opportunity notifications; and release
of matching keys so old exported IDs and project names can be imported again.

The portable backup does not depend on WAL/SHM sidecars. Contribution/audit
history, Tender submissions/chases/reminders, reminder read state and regions
are retained. The marker commits with the clear. New imports survive restart.

Backup failure and a later transactional failure leave no partial clear. Two
separate reset processes perform one reset and create one backup. An existing
worker's write waits during reset, then its new record survives. An empty
register gets a completion marker without a fabricated activity entry.

server errors and references, Retry feedback/recovery, HTML gateway errors,

DEPLOYMENT

Use the changed-files ZIP over the previously delivered v3.5, or the full ZIP
for a complete code update. Both contain built browser assets and the blank
template. Preserve live databases, uploads and environment settings.

The GitHub workflow preserves server-owned passenger_wsgi.py. Merge the new
adapter while keeping local interpreter/environment setup. Install requirements
and run tools/check_runtime.py with the Python actually used by Passenger.
Restart the configured application after all files have been copied.

The first Tender initialization can trigger the requested clear. A populated
register is backed up beside its active Tender database under upgrade_backups/,
with a filename beginning <database-stem>-before-opportunity-reset-v351-.
Read UPDATE_INSTRUCTIONS_V3.5.1.txt in the ZIP for full installation and recovery
steps. The completion marker prevents later starts from clearing new projects.

POSSIBLE REMAINING HOST ISSUE

If an error continues after deploying 3.5.1, use the displayed reference to
find the actual traceback in the application/Passenger log. Differences in
Python dependencies, SQLite/timezone support, database paths or permissions,
missing files, storage availability, or older processes are possible causes;
none has been established as the screenshot's production cause.
