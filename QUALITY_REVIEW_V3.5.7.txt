REQUESTED OPPORTUNITY BEHAVIOR

Rejection notes are optional. An authorised creator or administrator assigning a
nonempty team selection automatically approves the opportunity, including an expired
entry. Manual approval also accepts expired entries. Removing assignments does not
reverse an approval. Date changes, imports and deadline sweeps leave approved
opportunities approved. People-only assignment retains the normal decision workflow.

Approved opportunities offer Quoted and Not quoted. Not quoted moves an unquoted
opportunity to Rejected with an optional note. Quoted requires a nonnegative
electrical services submission value (zero is permitted), selected builders and a
valid optional submission team. Note, quote number and submitted date may be blank;
a blank date defaults to the regional date. The opportunity stays approved and
retains durable submission links, while actual Tender submissions appear in Projects
and Project Chase-up.

The optional Link field and multiple builders remain available; shared opportunity
contact/email fields remain absent. Historical source contact information is
retained. Cards keep their exact deadline and use larger coloured day labels:
overdue and up to three days red, four to seven days yellow, and more than seven
days green. Undated entries remain supported. Regional dates and the existing themes
are retained, including mobile quote and assignment controls.

QUOTATION, PERMISSIONS AND AUDIT

Quote conversion checks live account/team authority and the current opportunity
revision. It creates one submission per selected builder within the existing
grouped-project model. Submission creation, opportunity links, audit entries,
notifications and cache-generation invalidation commit in one SQLite transaction.
The same normalized retry returns the original links without duplicate records;
changed retries return a conflict. Simultaneous requests create one group. Injected
builder and notification failures roll back every write. A conflicting existing
project name produces an actionable error instead of overwriting an unrelated Tender
project. Decisions, assignment approvals and quotations remain visible in activity
and user contributions; assignment recipients receive notifications.

MIGRATIONS AND EXISTING DATA

The catalogue advances from schema 31 to 32 with an additive excluded_categories
setting that defaults to every section included. Complete schema-31 databases avoid
replaying historical migrations. The upgrade uses the existing verified backup and
transactional validation path; incompatible constraints fail without committing a
partial upgrade. The release retains earlier deleted_at, builder_key, legacy
creator_id, related-table and foreign-key migration repairs, archives and rollback
checks.

The earlier owner-requested reset still uses retained records and its existing
completion marker. It does not clear later work again. A separate one-time
correction restores only active approvals supported by matching approval metadata
followed by a recorded system expiry. Ambiguous, deleted and retired records are
skipped. A verified private backup precedes corrections; decision metadata and
history remain intact, with an explicit system correction event. Full Tender startup
runs schema initialization, the existing reset and then correction. Standalone
schema initialization does not require application settings. Repeated startup and
backup/late-failure rollback are covered.

ESTIMATE SECTION TOTALS AND PORTABILITY

Every section starts On. Off retains items, components, quantities, rates and raw
section prices, while excluding the section from aggregate material, hours, labour,
direct cost, overhead and quoted value. Included totals also drive crew/time
previews, project lists and cached dashboard figures. Turning all sections Off
yields zero aggregate costs and hours; turning them back On restores the original
totals. Edit permission and optimistic revision checks apply to each saved change.

Exclusions survive reload, restart, project copies, portable JSON export/import and
revision restore. Older snapshots default to all On. One canonical category key
handles repeated spaces, tabs and nonbreaking spaces consistently across switches,
calculations, grouping, ordering, deletion and import, without rewriting raw
category snapshots. Deleted or renamed final category members release obsolete
exclusions. Delayed project GET responses cannot overwrite a newer saved selection:
request invalidation and revision guards protect reads before and after asynchronous
review.

Public shared estimates identify excluded sections and items and explain the
included top total while retaining reference prices. Excel preserves raw detail
prices and initializes editable On/Off inclusion cells from the saved section
settings. Formula-linked aggregate, work-type and overview totals follow those
flags; excluded category summaries are labelled. Workbook tests cover changing flags
and mixed item markups. The existing blank opportunity import template and its
supported Link/multiple-builder import path remain available.
